# Decisions

Low-impact decisions taken while building the project, with the reason. Newest last. The
contract they shape is `docs/PLAN.md`.

| # | Date | Decision | Choice | Why |
| --- | --- | --- | --- | --- |
| 1 | 2026-11-02 | Source dataset | TPC-DS, generated locally; SF0.01 in CI, SF1 for the default demo, SF10 for the documented heavy run, SF100 described only | It is the only open, scalable retail schema with items, stores, warehouses, inventory, promotions, customers, sales and returns, and prices and costs on every line. Real sets lose: UCI Online Retail II (CC BY 4.0) is 1.07M rows with no hierarchy; Open Prices (ODbL) is crowd-sourced prices with no OLTP shape; Olist (CC BY-NC-SA), Instacart (non-commercial, no prices), M5 and Favorita (Kaggle login plus competition rules) and Dunnhumby (no licence text) cannot be scripted for anonymous, reproducible downloads |
| 2 | 2026-11-02 | TPC-DS generator | DuckDB 2.0.0 with its `tpcds` extension (v2.0.0, installed from the DuckDB extension repository at run time) | One pip dependency, no compiler, writes Parquet directly. Measured on the owner's laptop (memory limit 6 GB, 8 threads): SF1 generates in 8.3 s with a 1.07 GB peak, SF10 in 58.6 s with a 5.21 GB peak and 2.78 GB of zstd Parquet. dsdgen is never redistributed by this repo and generated data is never committed. DuckDB 2.0 switched dsdgen to TPC-DS v4 output, so DuckDB minor updates move by hand with the expected row counts (Dependabot ignore) |
| 3 | 2026-11-02 | TPC licence notice | Every place that shows timings says they are not TPC-DS benchmark results and are not comparable to TPC Benchmark results | Clause 4c(3) of the TPC EULA allows publishing results only with that statement; TPC, TPC-DS and TPC Benchmark are TPC trademarks |
| 4 | 2026-11-02 | Image and tool versions | apache/nifi 2.12.0, clickhouse/clickhouse-server 26.3 LTS, postgres 18.6-alpine, rustfs/rustfs 1.0.4, prom/prometheus v3.15.1, grafana/grafana 13.2.5, postgres-exporter v0.20.1, grafana-clickhouse-datasource 4.23.2, PostgreSQL JDBC 42.7.14, dbt-core 1.10.x with dbt-clickhouse 1.10.3 | Current stable lines on 2026-11-02. ClickHouse takes the LTS line. dbt-core 1.12 also resolves with dbt-clickhouse 1.10.3, but the adapter documents support up to dbt-core 1.10. MinIO's community image is gone, so the S3-compatible store is RustFS, as in the sibling repos |
| 5 | 2026-11-02 | NiFi file format | Parquet, through nifi-parquet-nar and nifi-hadoop-libraries-nar 2.12.0 added to a custom image (sha256-verified); Avro with an embedded schema is the fallback | The NiFi 2.12 convenience image has no Parquet support (both NARs sit in an inactive build profile); both are on Maven Central. ClickHouse reads either format from S3, so the fallback changes only the writer and the load statement |
| 6 | 2026-11-02 | NiFi transport and auth | The image's HTTPS port with single-user credentials from env; the cycle trigger is a processor-level plain-HTTP listener on its own port | The 2.x image dropped plain HTTP for the UI and API. | 7 | 2026-11-02 | Where the CLI runs | On the host for data generation, OLTP load, NiFi deploy, cycles, checks and reports | Avoids moving gigabytes through Windows bind mounts and keeps DuckDB outside the Docker VM memory budget |
| 8 | 2026-11-02 | Compose profiles | `COMPOSE_PROFILES=core` in `.env`; profiles `core`, `monitoring`, `workload` | Every service has a profile and a bare `docker compose up` still starts the loop |
| 9 | 2026-11-02 | Control database | A separate Postgres for the registry and audit | An OLTP under load must not stall the audit trail; it costs 256 MiB |
| 10 | 2026-11-02 | Sales channels | Store and web kept, catalog dropped | The catalog channel has no store or zone, adds about 30% volume and carries no pricing signal |
| 11 | 2026-11-02 | Business dates | Every TPC-DS date shifts by 8,372 days (23 x 364), so sales 1998-01-02..2003-01-02 become 2020-12-04..2025-12-04; anchor business date 2025-12-04; the workload's business clock continues from there | Weekdays and seasons are kept; pricing reads `as_of` from the cycle, never the wall clock, so runs are repeatable; `updated_at` (wall clock) only drives watermarks |
| 12 | 2026-11-02 | Deterministic randomness | `u(key, salt)` from md5 in DuckDB SQL, mirrored in Python | Stable across engine versions, unlike `hash()`, and reproducible in tests and the workload |
| 13 | 2026-11-02 | Reproducibility claim | Manifests hold row counts, file sha256 and an order-independent content hash per table | Parquet bytes may differ across writer versions; the content hash is what two runs must share |
| 14 | 2026-11-02 | Schema changes | Idempotent DDL and a reset (`make down`) instead of a migration tool | A demo with generated data needs no migrations |
| 15 | 2026-11-02 | Watermarks | Taken from the OLTP clock with a 2-minute overlap and committed only after the load succeeds | Commit-time skew is covered, duplicates collapse in ReplacingMergeTree, and a failed cycle re-extracts the same window |
| 16 | 2026-11-02 | Raw file layout | S3 keys include the cycle and the extract run id | A rerun never reads stale parts |
| 17 | 2026-11-02 | Extract paging | Full loads paged by GenerateTableFetch on the dense primary key; incremental loads as one streamed query split by Max Rows Per Flow File | Parallel pages where volume is large, one cheap query where it is small |
| 18 | 2026-11-02 | Parquet codec in NiFi | SNAPPY | Bundled codec, no native zstd dependency in NiFi |
| 19 | 2026-11-02 | Stage barrier | NiFi process groups with FlowFile Concurrency "Single FlowFile Per Node" and Outbound Policy "Batch Output"; item status in the audit DB; Wait/Notify as the fallback | The stage token leaves only when every item is done, cycles serialize for free and nothing counts fragments; the spike in PR 4 confirms it |
| 20 | 2026-11-02 | Audit writes | Item-level rows go to an append-only `audit.step_event` through PutSQL; a trigger keeps the current state in `audit.step`; functions with results run through ExecuteSQLRecord on the stage token | PutSQL never needs a result set, and the token's content is disposable |
| 21 | 2026-11-02 | Reverse-load order | One NiFi group per target, chained: zone prices, store overrides, promo prices, shelf labels | Prices land before the labels that depend on them, by construction |
| 22 | 2026-11-02 | ClickHouse raw tables | ReplacingMergeTree(version) ordered by the primary key, `version` as UInt64, no partitioning, read with FINAL in staging | Overlap duplicates and re-loads collapse to the highest version |
| 23 | 2026-11-02 | Cycle-scoped dbt models | Incremental append plus a pre-hook that deletes the cycle's own rows | Re-running a cycle replaces its rows without FINAL |
| 24 | 2026-11-02 | Price history | SCD2 from the OLTP trigger history, not a dbt snapshot | One history covers manual and engine changes |
| 25 | 2026-11-02 | dbt packages | None; the few generic test macros live in the project | No network at build time |
| 26 | 2026-11-02 | Reconciliation checksum | Row count, sum of price cents and a key-weighted sum, computed identically in Postgres and ClickHouse | Proves nothing was lost in transit and that the applied values match |
| 27 | 2026-11-02 | Cycle schedule | An interval in the job registry, polled by NiFi every minute | No cron parser; the registry decides |
| 28 | 2026-11-02 | Scales per run | `make demo` defaults to SF1; CI runs SF0.01 | SF1 shows zones and ladders; SF0.01 fits CI time |
| 29 | 2026-11-02 | Alerts | Provisioned in Grafana and recorded in `audit.alert`, with no external contact point | Nothing to send to on a laptop |
| 30 | 2026-11-02 | Dependabot | Monthly, 7-day cooldown, one minor-and-patch group per ecosystem, semver-major ignored, auto-merge workflow in protected mode | The portfolio's Dependabot policy; main is protected with the CI jobs as required checks, so auto-merge waits for them |
| 31 | 2026-11-02 | Diagrams | D2 v0.9.0 (sha256-checked), ELK, the portfolio `_style.d2`, SVGs committed and checked in CI | Portfolio standard; same bytes in CI and on a laptop |
| 32 | 2026-11-02 | Content hash | `sum(md5_number_lower(CAST(row AS VARCHAR)))::HUGEINT % 2^64` per table, plus the row count | In DuckDB 2.0 `struct_pack(COLUMNS(*))` builds one struct per column, and a sum of `md5_number` returns a lossy DOUBLE |
| 33 | 2026-11-02 | Reading generated Parquet | `read_parquet(..., hive_partitioning = false)` | Paths such as `sf=1/` would otherwise add an `sf` column; ClickHouse reads of these folders may need the same care |
| 34 | 2026-11-02 | Item versions and NULL values in TPC-DS items | Versions of an item are ordered by `i_item_sk` (dsdgen assigns it in start-date order) and the current version is the highest sk, not the plan's `i_rec_end_date IS NULL`; NULL `i_current_price` becomes 0.99 + 49·u, NULL `i_wholesale_cost` 45..75% of the price, NULL `i_rec_start_date` the previous version's end + 1 day (else its start + 1 day, else 1997-10-27, the earliest start TPC-DS assigns) | SF1 has 45, 46 and 46 such item versions out of 18,000 (none at SF0.01), and dsdgen injects NULLs into the record dates too, so dates cannot decide which version is current; every price, cost and history row must be set and every history interval non-empty |
| 35 | 2026-11-02 | Other missing measures on sales lines | unit price falls back to list price, then item price; net to quantity x price; discount to 0; unit cost to the item's wholesale cost; lines with no sold date or quantity are dropped and counted | Keeps the sales volume while every OLTP column stays NOT NULL |
| 36 | 2026-11-02 | Returns after the anchor | Dropped and counted | A return dated after the last sale would be a future event for the OLTP |
| 37 | 2026-11-02 | Seed table creation | Every table is created from `contract.py` (NOT NULL, `version` 1, `updated_at` at the anchor, `updated_by` 'seed'), then filled with `INSERT BY NAME` | The Parquet shape cannot drift from the contract |
| 38 | 2026-11-02 | Price ending grid | Round to cents half up, then to the nearest grid price with ties going up; promo prices round down; one cents lookup built from `rules.price_ending_band` | Same rule in SQL and Python, and a promo price never rounds above its target depth |
| 39 | 2026-11-02 | Ladder repair of the seed prices | Python (`synth.repair_zone`), raises only: PACK then TIER, repeated until stable | Raising only toward smaller packs and higher tiers always converges; SQL would need a recursive fixpoint |
| 40 | 2026-11-02 | Stores and zones | Stores are TPC-DS current store versions; store zones = clamp((stores + 2) // 4, 1, 8) plus one WEB zone | Matches the plan's intent without counting historical store versions |
| 41 | 2026-11-02 | KVI share | At least 5 products and ceil(2%) by 365-day store units; tier 1 is ceil(0.5%), at least 1 | Small scales still get a usable KVI list |
| 42 | 2026-11-02 | Supplier cost history | 24 monthly points 2024-01-01..2025-12-01; cost capped at 0.85 x the version price and at 0.98 x (1 - min margin) x the lowest zone price, except the 3% of products seeded 3 points below the minimum | Only the intended products start below the minimum margin, so the margin-floor rule has known work to do |
| 43 | 2026-11-02 | Promotions, brands and suppliers | Promotions apply to channel ALL and last 7..28 days; brands and suppliers are keyed by TPC-DS id and named with min(name) | TPC-DS brand and manufacturer names are not one-to-one with their ids |
| 44 | 2026-11-02 | Control SQL tests | Run in their own database `control_test` on the control Postgres, reset by a session fixture | A running demo's audit data in `control` is never wiped by a test run |
| 45 | 2026-11-02 | Control functions | SECURITY DEFINER with a fixed `search_path`; `nifi` gets EXECUTE, INSERT on `audit.step_event` and INSERT/SELECT/UPDATE only on the four tables PutDatabaseRecord writes | NiFi can do exactly what its flows need and cannot change the registry or drop anything |
| 46 | 2026-11-02 | Partition column for composite keys | `product_id` when it is part of the key, otherwise the first numeric key column | `store_id` or `warehouse_id` have too few values to split pages evenly |
| 47 | 2026-11-02 | Registry seed upsert | Updates only structural columns; `enabled`, `page_rows`, SLA, owner, schedule and `nifi_process_group_id` keep operator and deploy edits | Re-running `control init` never undoes an operator's change |
| 48 | 2026-11-02 | Cycle reruns | `start_cycle` with a rerun id resets a failed cycle (new `started_at`, `attempt` + 1) and refuses an unknown or non-failed cycle; a busy call returns the running cycle's id with status `busy`; at most one running cycle (partial unique index) | A crashed cycle is rerun with the same id, and two cycles never overlap |
| 49 | 2026-11-02 | Scheduled cycles | `start_cycle_if_due()` starts the incremental cycle itself (requested by `schedule`) and returns its id | The NiFi token needs the id from one call |
| 50 | 2026-11-02 | Extract plans | `p_mode` NULL means the cycle's mode; a table without a watermark is always planned full | A new table joins incrementally without a manual full load |
| 51 | 2026-11-02 | Watermark commit | `commit_watermarks` raises unless the cycle has a succeeded `load` run | A failed load re-extracts the same window |
| 52 | 2026-11-02 | Run and cycle endings | `end_run` is idempotent for ended runs; `finish_cycle` marks still-running runs failed when the cycle fails | Retries of the gates are harmless and no run stays open after a failure |
| 53 | 2026-11-02 | Reconcile with no checks | Passes, and a pass resolves an earlier `reconcile_failed` alert | A cycle with no changes has nothing to reconcile |
| 54 | 2026-11-02 | Reconcile keys | `zone_id` and `category_id` NOT NULL default 0 in the reconcile tables | They are part of the primary key; 0 stands for "all" |

| 57 | 2026-11-02 | OLTP DDL | Tables, constraints and indexes rendered from `contract.py` by `oltp/ddl.py`; triggers, apply functions and roles stay SQL files (`040`..`060`) | One source of truth for every column; no hand-written table DDL to drift |
